# 倩岚汪 — UI 设计基线（Warm Flat / Fullscreen HUD）

- **版本：** 1.0
- **状态：** 正式 UI 设计基线
- **依据：** PRD、游戏内容设计文档和技术设计文档
- **平台：** 桌面浏览器、手机竖屏、手机横屏

## 1. 设计定位

全屏 3D 宠物房间是游戏的视觉主体，使用暖色简约扁平（Warm Flat）界面，悬浮式平视显示层（HUD）覆盖在 React Three Fiber 画布之上。优先让玩家观察和触摸宠物，不再以传统网页图文卡片为主。低状态轻量提示，长期离线非惩罚式养成；互动的数据结算交给服务端。

## 3. 全屏主界面

1. **中心舞台：** 全屏 3D 房间，中心区域不摆放固定信息面板。R3F 每帧独立更新。
2. **左上：** 头像、名字、亲密度。点击打开档案卡，可查看性格、年龄、领养信息。
3. **中上：** 饱腹、水分、精力、清洁四个环形状态按钮；点击查看具体值，触摸端不依赖 hover。
4. **右上：** 服务器同步状态、设置。同步状态必须区分正在保存、已同步、失败、未连接。
5. **中部：** 宠物被触摸、互动完成或需求变化时显示轻量气泡，限时消退，不阻断操作。
6. 底部提供抚摸、点戳、呼唤、饮食、玩球和梳毛。饮食展开狗粮和清水子菜单。

## 4. 互动规则

- 默认工具为抚摸，玩家直接触摸宠物即可触发本地反馈，无需反复切换。
- 呼唤是瞬时行为，饮食在二级托盘展开。抚摸、点戳、玩球和梳毛是互斥的工具模式。
- 正式宠物模型应具备 Head / Chin / Back 可区分的触摸碰撞区；抚摸位置、方向、时长应改变动作反馈。
- 玩球模式下拖拽或点击舞台决定抛球；正式版本需明确力度和方向。
- 梳毛模式应提供完成度和粒子表现；触摸控制应与镜头操作隔离。
- 高频指针坐标和动画运算在场景内部使用 ref 与 useFrame；低频面板和工具状态使用 Zustand。
- UI 只发送交互请求，持久化状态需要服务端确认后才能更新；请求失败时显示明确错误与重试入口。

## 5. 响应式布局

- **桌面：** 顶部三段布局，底部水平动作坞。
- **手机竖屏：** 档案和设置第一行、四维状态第二行，工具尺寸适配拇指操作。
- **手机横屏且高度不足：** 底部动作坞移至右侧竖排，减少对宠物主体的遮挡。
- 使用 100dvh 和安全区 env(safe-area-inset-*) 适配浏览器动态工具栏、刘海屏及系统手势区。
- 所有图标操作带文字或 aria-label，模态窗口允许通过 Escape 关闭；保留焦点轮廓，减少动效偏好需被尊重。

## 6. 领养与离线回归

- **首次领养：** 选择活泼/黏人/慢热 → 取名 → 确认带回家。仅接入真实账号和宠物 API 后才启用持久化。
- **离线回归：** 接收到服务端按 UTC 时间结算的时间跨度及状态差异后，再展示简短问候便签和数值变化。不从客户端本地时间凭空生成故事或假装已经结算。
- **同步状态：** 顶部云图标可以打开账号面板，显示连接、登录、待领养、同步中、已同步和重试状态。

## 7. 本次落地范围

- 全屏 R3F 房间已接入 Akita 骨骼模型。待机、点击与互动工具会驱动动画。HUD 提供状态环、档案、画质设置以及桌面与移动端布局。
- 访客使用示例宠物“团子”试玩。注册并领养后，档案和状态环显示服务端存档，完成动作后更新。
- 已实现场景里的分部位抚摸、沿背梳毛、呼唤靠近、到碗旁吃喝、叼球和自主打盹。
- 后续接入正式宠物模型和音效，在线上完成账号 API 首次安装和验证。

新增犬种时保留 GameHUD 与 UI 设计令牌；犬种专属的模型、动作和触摸差异由场景适配层处理，避免每增加一种犬就重做界面。
