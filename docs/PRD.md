# 倩岚汪 — 产品需求文档（PRD）

- 文档版本：0.1
- 项目状态：立项与技术方案阶段
- 游戏名称：倩岚汪（暂定）
- 类型：3D 宠物养成互动
- 首发宠物：柴犬
- 平台：桌面与移动端 Web 浏览器
- 核心参考：任天狗（Nintendogs）的陪伴、触摸互动、训练和宠物自主行为体验

## 1. 产品定位

玩家拥有一只属于自己的柴犬。玩家可以通过触摸、呼唤、喂食、玩耍和日常照顾与它建立关系。柴犬会根据需求、情绪、性格和环境自主行动；玩家离开后，宠物的生活状态仍会按照现实时间自然变化。

产品的核心价值是持续陪伴和有反馈的互动。养成数值用于支撑宠物行为，不让数值管理压过陪伴体验。

## 2. 设计原则

1. 宠物先像一只狗，再像一个游戏角色：动作、反应和行为要自然，有等待、观察、犹豫和自发活动。
2. 互动必须有即时反馈：触摸位置、力度和持续时间应影响宠物反应；动作、表情、声音和状态变化保持一致。
3. 宠物有自主生活：玩家不操作时，柴犬会探索、嗅闻、休息、玩耍和观察。
4. 长期陪伴不采用惩罚式设计：离线会产生需求变化，但不设置死亡、永久损失或必须定时上线的惩罚。
5. 云端数据为准：不同设备登录同一账号后，看到同一只宠物及一致的状态。
6. 第一阶段聚焦一只柴犬，把模型、动画、互动和行为打磨好，再扩展宠物种类。

## 3. 目标用户与使用场景

- 希望拥有轻松、温馨宠物陪伴体验的玩家。
- 使用电脑或手机浏览器，在碎片时间进入游戏互动。
- 可能在不同设备间切换，希望随时接续上次的养成进度。
- 希望偶尔打开网页，也能看到宠物在自己的小空间里生活。

## 4. 核心游戏循环

1. 玩家注册或登录。
2. 首次进入时领养柴犬，为它取名字。
3. 进入宠物房间，观察柴犬当前的动作、情绪和需求。
4. 通过抚摸、呼唤、喂食、喝水、玩球、梳毛等行为互动。
5. 柴犬即时反馈，并逐步形成亲密关系。
6. 玩家离开后，宠物继续按现实时间变化。
7. 下次登录时，服务器结算离线期间的状态，玩家继续照顾它。

## 5. 首发宠物：柴犬

### 5.1 角色特征

首发是一只具有柴犬外形特征的卡通写实风格幼犬：立耳、卷尾、短而结实的身体、清晰的眉部与口鼻表情。整体比例偏可爱，但保留柴犬的体态和动作特点。

### 5.2 性格

首版提供三种性格倾向，影响行为概率和互动偏好，不形成强弱差异：

- 活泼：更容易主动追逐玩具，精力消耗稍快。
- 黏人：更频繁靠近玩家，对抚摸和呼唤反应更积极。
- 慢热：需要更多互动建立信任，熟悉后会主动靠近。

性格在领养时选择，后续不提供随意重置。性格参数由服务端保存。

### 5.3 名字

玩家领养时为柴犬取名。首版允许修改名字，修改行为写入云端存档。

## 6. 第一阶段功能范围

### 6.1 账号与存档

- 邮箱和密码注册、登录、退出。
- 一个账号对应一只首发柴犬。
- 登录后从服务器加载宠物档案和状态。
- 玩家在另一台设备登录后，继续同一份存档。
- 关键互动由服务器确认并保存。
- 登录态使用安全的服务端 Session Cookie。

### 6.2 3D 宠物房间

- 一个完整的室内宠物活动空间。
- 柴犬位于场景中央附近，可在限定区域自主移动。
- 支持桌面鼠标和手机触控。
- 相机采用稳定的第三人称观察视角，首版不做自由复杂镜头。
- UI 与 3D 场景分层，状态和工具不遮挡宠物主体。

### 6.3 抚摸与呼唤

- 玩家可以触摸头部、下巴、背部。
- 不同部位触发不同反应，例如眯眼、摇尾、靠近、躲闪或回头。
- 连续快速点击不应重复播放同一段动画；需要动作冷却和反应组合。
- 呼唤按钮触发名字呼唤反馈，柴犬根据距离、心情和性格回应。
- 语音识别呼唤作为后续增强项，首版先使用明确的界面按钮。

### 6.4 喂食与喝水

- 玩家选择食物并放到食盆附近。
- 柴犬能够靠近食盆、低头进食、结束后离开。
- 喂食恢复饱腹状态；不同食物可以有不同恢复量。
- 水盆互动恢复口渴状态。
- 食物和水的使用记录进入互动日志，避免重复请求造成重复结算。

### 6.5 玩耍

- 首版提供一个球类玩具。
- 玩家将球投出，柴犬可以追逐、叼起并返回。
- 柴犬可能因性格和精力不同而改变追逐意愿。
- 玩耍消耗精力并提升心情和亲密度。

### 6.6 清洁

- 首版提供梳毛互动。
- 梳毛有明确的手部操作反馈和柴犬反应。
- 清洁度随时间缓慢下降，梳毛后恢复。
- 洗澡、吹干和复杂清洁工具放入后续版本。

### 6.7 自主行为

首版至少实现以下自主行为：

- 待机、观察、眨眼、转头。
- 嗅闻地面、寻找目标。
- 在房间内短距离走动。
- 坐下、趴下、伸懒腰、打哈欠。
- 摇尾、靠近玩家、短暂撒娇。
- 精力较低时主动寻找位置休息并进入睡眠。
- 被互动打断后根据当前行为决定是否回应。

自主行为采用行为选择系统，行为有权重、前置条件、持续时间和冷却时间，避免每隔固定时间随机切换动画。

### 6.8 成长与关系

- 记录宠物出生或领养时间，并按现实时间计算年龄。
- 亲密度由持续、正向的互动累积。
- 性格影响反应，不影响玩家获得基础功能。
- 首版展示年龄、亲密度和当前状态。
- 幼犬到成犬的模型变化与复杂成长阶段放入后续版本。

## 7. 宠物状态模型

首版使用 0—100 的状态值：

| 状态 | 含义 | 自然变化 |
|---|---|---|
| 饱腹 | 是否需要进食 | 随时间下降 |
| 水分 | 是否口渴 | 随时间下降 |
| 精力 | 活动与休息能力 | 清醒时下降，睡眠时恢复 |
| 清洁度 | 毛发与身体清洁程度 | 缓慢下降 |
| 心情 | 当前愉悦程度 | 随需求和互动变化 |
| 亲密度 | 与玩家建立的关系 | 通过正向互动增加，不因离线减少 |

年龄由领养时间计算，不作为可任意修改的数值。

### 7.1 离线变化规则

- 以服务器 UTC 时间计算经过时长。
- 每次读取宠物或提交互动时，先结算上次更新时间至当前时间的自然变化。
- 不要求服务器为每只宠物运行常驻定时任务。
- 饱腹、水分和清洁度按时间变化；精力根据睡眠状态恢复或消耗。
- 数值限制在 0—100。
- 长时间离线后宠物可以疲惫或饥饿，但不会死亡、永久受伤或丢失进度。
- 亲密度不因玩家离线而衰减。

具体衰减速率先放在统一配置中，通过测试和试玩调整，不在多个模块中散落硬编码。

## 8. 界面与交互要求

### 主场景

- 3D 宠物房间占据主要可视区域。
- 顶部显示宠物名字、年龄和简洁状态。
- 底部提供抚摸、呼唤、喂食、喝水、玩耍、梳毛入口。
- 次级面板展示背包、宠物资料和设置。
- 低状态提醒采用轻量提示，不使用阻断式弹窗。

### 适配要求

- 桌面端支持鼠标、键盘和常见宽屏比例。
- 移动端支持触摸、竖屏与横屏布局。
- 交互按钮适合手指点击，避免依赖悬停状态。
- 3D 画面提供性能降级选项。

## 9. 第一版验收标准

1. 用户能够注册、登录和退出。
2. 首次登录能够领养柴犬并设置名字和性格。
3. 桌面和手机浏览器都能进入 3D 房间。
4. 抚摸、呼唤、喂食、喝水、玩球和梳毛有可辨识的动画或行为反馈。
5. 玩家停止操作时，柴犬会持续执行自主行为。
6. 玩家关闭页面数小时后再次进入，宠物状态按服务器时间正确结算。
7. 同一账号在两台设备登录，宠物名字、状态和互动结果保持一致。
8. 重复提交同一互动请求不会重复扣除物品或重复增加状态。
9. 客户端修改系统时间不会影响宠物自然变化。
10. 离线或网络异常时，界面明确显示同步状态，不把未确认的本地变化伪装成已保存。

## 10. 暂不纳入第一版

- 多犬种、多宠物和繁殖系统。
- 玩家之间拜访、聊天、交易和排行榜。
- 复杂比赛、任务剧情和经济系统。
- 付费商城、广告和抽卡。
- 完整语音识别训练。
- 高复杂度房屋装修和开放世界探索。

## 11. 核心风险

- 柴犬模型和动画质量决定第一印象，需要尽早验证模型骨骼、动作数量和表情表现。
- 自主行为如果只依赖随机动画，会显得机械；必须结合需求、性格和环境目标选择行为。
- 离线状态结算和多设备并发互动必须由服务端统一处理。
- 手机浏览器的 GPU、内存和触控能力差异较大，需要真实设备测试。
