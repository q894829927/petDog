# 倩岚汪 — 产品需求文档（PRD）

- 文档版本：0.2
- 项目状态：原型已运行，产品系统与多犬种架构设计中
- 游戏名称：倩岚汪（暂定）
- 类型：3D 宠物养成互动
- 当前验证犬种：秋田犬（Akita）
- 产品规划：逐步接入多种犬类，具体犬种按模型、骨骼和动画资源完成度确定
- 平台：桌面与移动端 Web 浏览器
- 核心参考：任天狗（Nintendogs）的陪伴、触摸互动、训练和宠物自主行为体验


## 1. 产品定位

玩家领养并照顾一只具有独立外观、动作和性格的宠物犬。产品规划支持多种犬类，每种犬拥有自己的模型、骨骼适配、动作表现、表情、叫声和犬种行为倾向。玩家可以通过触摸、呼唤、喂食、玩耍、训练、散步和日常照顾与宠物建立长期关系。

不同犬种共享一套基础互动、养成、场景和行为系统；犬种差异通过资源配置、动作扩展和行为参数表现。每只宠物还拥有独立性格、偏好和成长记录。

产品的核心价值是持续陪伴和有反馈的互动。养成数值用于支撑宠物行为，不让数值管理压过陪伴体验。


## 2. 设计原则

1. 宠物先像一只真实的狗，再像一个游戏角色：动作、反应和行为要自然，有等待、观察、犹豫和自发活动。
2. 互动必须有即时反馈：触摸位置、力度和持续时间应影响宠物反应；动作、表情、声音和状态变化保持一致。
3. 通用玩法与犬种表现分离：抚摸、喂食、玩耍、训练和照料由通用系统提供；各犬种通过自己的模型、动画、触摸映射和专属动作呈现差异。
4. 犬种特征与个体性格分离：犬种定义体态、动作资源和基础行为倾向；同一犬种的不同个体仍可具有不同性格和偏好。
5. 宠物有自主生活：玩家不操作时，宠物会探索、嗅闻、休息、玩耍和观察。
6. 长期陪伴不采用惩罚式设计：离线会产生需求变化，但不设置死亡、永久损失或必须定时上线的惩罚。
7. 云端数据为准：不同设备登录同一账号后，看到同一只宠物及一致的状态。
8. 先用当前秋田犬原型验证通用框架，再通过犬种适配配置逐步增加其他犬类；不为每个犬种重写整套玩法。

## 3. 目标用户与使用场景

- 希望拥有轻松、温馨宠物陪伴体验的玩家。
- 使用电脑或手机浏览器，在碎片时间进入游戏互动。
- 可能在不同设备间切换，希望随时接续上次的养成进度。
- 希望偶尔打开网页，也能看到宠物在自己的小空间里生活。


## 4. 核心游戏循环

1. 玩家注册或登录。
2. 从当前已开放的犬种中选择一只宠物，为它取名并选择个体性格。
3. 进入宠物房间，观察宠物当前的动作、情绪和需求。
4. 通过抚摸、呼唤、喂食、喝水、玩耍、梳毛和训练等行为互动。
5. 宠物根据犬种动作配置、个体性格和当前状态作出反馈，并逐步形成亲密关系。
6. 玩家解锁更多玩具、照料方式、训练项目和活动场景。
7. 玩家离开后，宠物继续按现实时间变化；下次登录时由服务器结算离线期间的状态。


## 5. 犬种、宠物个体与性格

### 5.1 多犬种规划

产品不固定使用某一种犬。当前原型使用 Dogs_Big_pack 的秋田犬（Akita）资源，已用于验证房间移动、吃喝、追球、呼唤、抚摸、梳毛和休息等功能。秋田犬是当前开发基准，不等于最终犬种名单。

后续犬种按资源准备情况逐步接入。每种犬需要提供模型、骨骼映射、基础动作、身体触摸区域、叫声和犬种专属动作。所有犬种复用通用互动、状态结算、物品、训练、场景导航和存档系统。

首阶段仍按一个账号拥有一只宠物设计；玩家可以从已开放犬种中选择领养。多犬同时饲养属于后续产品决策，不与多犬种资源接入绑定。

### 5.2 犬种差异

犬种差异由资源和参数表达，主要包括：

- 外观：体型、头部轮廓、耳朵、尾巴、毛色和毛发特征。
- 动作：不同犬种的待机、行走、奔跑、坐卧、进食、睡眠和互动动作。
- 表情：耳朵、眼睛、口鼻、头部和尾巴的表现方式。
- 触摸：根据各犬种模型建立头部、耳朵、脸颊、下巴、背部、腹部、四肢和尾巴等语义区域。
- 声音：吠叫、呜咽、喘气和其他反馈音效。
- 行为倾向：不同犬种可以有不同的活动偏好、探索倾向和玩具偏好。

犬种差异不应导致基础功能分叉。某个犬种没有专属动画时，使用适配层提供的通用动作或明确的替代动作。

### 5.3 个体性格

首版提供三种性格倾向，影响行为概率和互动偏好，不形成强弱差异：

- 活泼：更容易主动追逐玩具、探索和奔跑，活动消耗稍快。
- 黏人：更频繁靠近玩家，对抚摸和呼唤反应更积极。
- 慢热：更倾向先观察，需要更多互动建立信任，熟悉后会主动靠近。

性格独立于犬种。同一犬种可以领养出不同性格的个体；犬种提供基础倾向，个体性格在此基础上调整行为。性格在领养时选择，后续是否允许通过成长改变，留待成长系统设计。

### 5.4 名字与档案

玩家领养时为宠物取名。首版允许修改名字，修改行为写入云端存档。宠物档案记录犬种、性格、领养时间、亲密度和成长记录。

## 6. 第一阶段功能范围

### 6.1 账号与存档

- 邮箱和密码注册、登录、退出。
- 首阶段一个账号对应一只宠物犬；领养时从已开放犬种中选择。
- 登录后从服务器加载宠物档案和状态。
- 玩家在另一台设备登录后，继续同一份存档。
- 关键互动由服务器确认并保存。
- 登录态使用安全的服务端 Session Cookie。

### 6.2 3D 宠物房间

- 一个有纵深的带窗客厅。近处的地毯用于抚摸和接球，食水与休息区布置在两侧，中央地板连通前后。
- 宠物犬从前场出发，可走出地毯，在客厅地板上自主活动、追球和往返照料点。
- 支持桌面鼠标和手机触控。
- 默认采用近场第三人称视角。远抛时平滑拉开以跟上追球，接回后回到近场。按住进行抚摸或抓球时保持镜头稳定。
- UI 与 3D 场景分层，状态和工具不遮挡宠物主体。

### 6.3 抚摸与呼唤

- 直接触碰团子即可抚摸。可触及头顶、耳朵、脸颊、下巴、胸颈、肩背、腰臀、腿爪、尾巴和肚皮。团子会朝触碰的一侧回应。
- 团子清醒且身边有空间时，持续揉胸口或腰侧再松手，它会侧躺一小会儿露出肚皮。揉肚皮时，它会放松前爪。
- 轻点露出的尾根下方，玩家手用食指轻戳，团子收尾并原地转身面对玩家。拖过该处时继续抚摸。
- 不同部位触发不同反应，例如眯眼、摇尾、靠近、躲闪或回头。
- 连续快速点击不应重复播放同一段动画；需要动作冷却和反应组合。
- 呼唤按钮触发名字呼唤反馈，宠物犬根据距离、心情和性格回应。
- 语音识别呼唤作为后续增强项，首版先使用明确的界面按钮。

### 6.4 喂食与喝水

- 玩家选择食物并放到食盆附近。
- 宠物犬能够靠近食盆、低头进食、结束后离开。
- 喂食恢复饱腹状态；不同食物可以有不同恢复量。
- 水盆互动恢复口渴状态。
- 食物和水的使用记录进入互动日志，避免重复请求造成重复结算。

### 6.5 玩耍

- 首版提供一个球类玩具。
- 鼠标靠近地上的球时，玩家手做出准备抓握的动作。鼠标或手指按住球可以拿起，沿要投掷的方向拖动并松手。拖动距离影响抛球力度，轻点会把球放回原处。
- 球离手后受重力影响，落地后反弹并滚动。木地板比地毯弹得更高，地毯上的球会更快停下。
- 网球撞地越重，反弹声越响。场景音效在首次操作后启用，可在游戏设置里静音。
- 球停稳后，宠物犬可以追过去叼起并返回。
- 叼球回来、放下球后，团子会轻喘几下。
- 宠物犬可能因性格和精力不同而改变追逐意愿。
- 玩耍消耗精力并提升心情和亲密度。

### 6.6 清洁

- 首版提供梳毛互动。
- 选择梳毛后，从肩背按下朝尾巴拖动。梳过一段后，宠物会摇尾回应。触碰其他部位仍然是抚摸，球仍可抓取。
- 清洁度随时间缓慢下降，梳毛后恢复。
- 洗澡、吹干和复杂清洁工具放入后续版本。

### 6.7 自主行为

首版至少实现以下自主行为：

- 待机、观察、眨眼、转头。
- 嗅闻地面、寻找目标。
- 在房间内短距离走动。
- 走动和奔跑时，爪子在木地板上会发出清脆的轻响，在地毯上则是较轻的闷声。
- 坐下、趴下、伸懒腰、打哈欠。
- 摇尾、靠近玩家、短暂撒娇。
- 心情好时，宠物在站立待机或自主走动时会偶尔摇尾。心情和性格影响出现频率，每次摆动的次数、节奏和幅度略有不同。
- 团子格外开心时，偶尔会在摇尾时轻叫一声。两次轻叫至少间隔 45 秒。
- 精力较低时主动寻找位置休息并进入睡眠。
- 被互动打断后根据当前行为决定是否回应。

自主行为采用行为选择系统，行为有权重、前置条件、持续时间和冷却时间，避免每隔固定时间随机切换动画。

### 6.8 成长与关系

- 记录宠物出生或领养时间，并按现实时间计算年龄。
- 亲密度由持续、正向的互动累积。
- 性格影响反应，不影响玩家获得基础功能。
- 首版展示年龄、亲密度和当前状态。
- 幼犬到成犬的模型变化与复杂成长阶段放入后续版本。


### 6.9 语音交流与训练

- 玩家可以呼唤宠物名字，宠物根据距离、注意力、心情、性格和熟悉程度作出回应。
- 后续支持麦克风语音输入，识别名字和已学习的简单指令。
- 训练通过示范、重复、正确反馈和奖励建立动作记忆，不采用一次点击立即学会的方式。
- 首批训练动作规划为坐下、趴下、握手、过来、等待和转圈。
- 每项指令记录学习进度、成功率和熟练度；宠物可以出现犹豫、分心或执行失败等自然反馈。
- 语音不可用时保留屏幕按钮或文字指令作为替代输入。

### 6.10 玩具与日常照料扩展

在现有网球、食盆、水盆和梳毛基础上逐步增加：

- 飞盘：抛掷、追逐、跳跃接取和叼回。
- 绳结：玩家与宠物进行拔河，宠物根据体型和性格表现不同反应。
- 毛绒玩具：叼取、搬运、摇晃和自主玩耍。
- 发声玩具：声音吸引宠物注意并触发探索。
- 漏食玩具：通过嗅闻、推动和探索获得零食。
- 零食奖励：用于训练反馈和日常互动。
- 洗澡与吹干：形成完整清洁流程，清洁过程包含触摸反馈和情绪变化。

玩具应具备可被宠物自主发现和使用的能力，不能全部依赖玩家点击触发。

### 6.11 散步与探索

- 玩家选择散步路线，宠物跟随玩家移动。
- 路线中设置嗅闻点、可调查物品、环境声音和偶发事件。
- 宠物可以主动停下嗅闻、观察或对环境作出反应。
- 探索可获得纪念品、玩具、零食或照片主题。
- 后续逐步增加公园、街道、林间步道和海边等场景。

### 6.12 比赛与挑战

规划三类可重复游玩的项目：

- 服从训练：根据指令正确率、反应时间和连续完成情况评分。
- 飞盘比赛：根据投掷距离、接取表现和完成时间评分。
- 敏捷比赛：通过跨栏、钻隧道、绕桩和跳跃等障碍。

比赛奖励用于解锁装饰、玩具、称号和照片内容。比赛成绩不影响宠物的基础照料和陪伴体验。

### 6.13 房间与成长内容

- 增加狗窝、地毯、玩具架、窗边垫和其他家具。
- 环境物品可以成为宠物自主行为的目标，例如靠近窗边观察、从玩具架选择玩具。
- 增加项圈、围巾、帽子等装饰。
- 记录成长照片、训练成果、散步见闻和特殊互动事件。
- 通过亲密关系、训练和探索逐步解锁内容，不设置强制每日任务。

## 7. 宠物状态模型

首版使用 0—100 的状态值：

| 状态 | 含义 | 自然变化 |
|---|---|---|
| 饱腹 | 是否需要进食 | 随时间下降 |
| 水分 | 是否口渴 | 随时间下降 |
| 精力 | 活动与休息能力 | 清醒时下降，睡眠时恢复 |
| 清洁度 | 毛发与身体清洁程度 | 缓慢下降 |
| 心情 | 当前愉悦程度 | 随需求和互动变化 |
| 亲密度 | 与玩家建立的关系 | 通过正向互动增加，不因离线减少 |

年龄由领养时间计算，不作为可任意修改的数值。

### 7.1 离线变化规则

- 以服务器 UTC 时间计算经过时长。
- 每次读取宠物或提交互动时，先结算上次更新时间至当前时间的自然变化。
- 不要求服务器为每只宠物运行常驻定时任务。
- 饱腹、水分和清洁度按时间变化；精力根据睡眠状态恢复或消耗。
- 数值限制在 0—100。
- 长时间离线后宠物可以疲惫或饥饿，但不会死亡、永久受伤或丢失进度。
- 亲密度不因玩家离线而衰减。

具体衰减速率先放在统一配置中，通过测试和试玩调整，不在多个模块中散落硬编码。

## 8. 界面与交互要求

### 主场景

- 3D 宠物房间占据主要可视区域。
- 顶部显示宠物名字、年龄和简洁状态。
- 底部提供呼唤、饮食和梳毛。抚摸和抛球直接在 3D 房间内操作。
- 次级面板展示背包、宠物资料和设置。
- 低状态提醒采用轻量提示，不使用阻断式弹窗。

### 适配要求

- 桌面端支持鼠标、键盘和常见宽屏比例。
- 移动端支持触摸、竖屏与横屏布局。
- 交互按钮适合手指点击，避免依赖悬停状态。
- 3D 画面提供性能降级选项。

## 9. 第一版验收标准

1. 用户能够注册、登录和退出。
2. 首次登录能够从当前开放的犬种中领养宠物，并设置名字和个体性格；首个可用犬种以当前资源验收结果为准。
3. 桌面和手机浏览器都能进入 3D 房间。
4. 抚摸、呼唤、喂食、喝水、玩球和梳毛有可辨识的动画或行为反馈。
5. 玩家停止操作时，宠物犬会持续执行自主行为。
6. 玩家关闭页面数小时后再次进入，宠物状态按服务器时间正确结算。
7. 同一账号在两台设备登录，宠物名字、状态和互动结果保持一致。
8. 重复提交同一互动请求不会重复扣除物品或重复增加状态。
9. 客户端修改系统时间不会影响宠物自然变化。
10. 离线或网络异常时，界面明确显示同步状态，不把未确认的本地变化伪装成已保存。

## 10. 暂不纳入第一版

- 多犬同时饲养、繁殖系统；多犬种资源按阶段逐步接入，不要求首个可玩版本一次性提供完整犬种库。
- 玩家之间拜访、聊天、交易和排行榜。
- 复杂比赛、任务剧情和经济系统。
- 付费商城、广告和抽卡。
- 完整语音识别训练。
- 高复杂度房屋装修和开放世界探索。

## 11. 核心风险

- 每种犬的模型、骨骼和动画结构可能不同，需要建立稳定的犬种适配层，避免通用互动逻辑依赖某一模型。
- 自主行为如果只依赖随机动画，会显得机械；必须结合需求、犬种倾向、个体性格、记忆和环境目标选择行为。
- 离线状态结算和多设备并发互动必须由服务端统一处理。
- 手机浏览器的 GPU、内存和触控能力差异较大，需要真实设备测试。
