# 倩岚汪 — 游戏内容设计文档

- 文档版本：0.1
- 状态：目标设计，分阶段实施
- 产品类型：3D 宠物陪伴、养成与互动
- 核心参考：任天狗（Nintendogs）
- 当前验证原型：秋田犬（Akita）
- 产品方向：多犬种、可复用互动系统、个体性格与长期陪伴

## 1. 产品体验目标

让玩家感受到自己正在陪伴一只真实生活的狗。玩家进入游戏时，宠物可能正在睡觉、观察环境、嗅闻地面、寻找玩具或主动靠近玩家；玩家可以通过触摸、声音、训练、照料和玩耍与它建立关系。

游戏体验围绕四个支柱展开：

1. 生命感：宠物在没有玩家输入时也会自主活动，并对环境变化作出反应。
2. 可理解的互动：玩家做出的动作能得到及时、明确且符合犬只身体语言的反馈。
3. 个体差异：犬种和性格让宠物表现不同，同一犬种也会形成不同的个体。
4. 长期陪伴：训练、探索、照片、成长记录和生活空间让关系持续发展。

## 2. 多犬种与复用原则

### 2.1 产品范围

《倩岚汪》不固定为柴犬或其他单一犬种。当前项目使用秋田犬（Akita）作为开发验证原型，后续按资源质量和适配进度逐步导入其他犬种。

首阶段仍按一个账号领养一只宠物设计。多犬种意味着玩家可以从已开放犬种中选择宠物，不等于首阶段就支持同一账号同时饲养多只犬。

### 2.2 三层内容结构

| 层级 | 负责内容 | 是否跨犬种复用 |
|---|---|---|
| 通用宠物系统 | 抚摸、呼唤、喂食、喝水、玩耍、梳毛、训练、物品、状态、寻路和存档 | 所有犬种共享 |
| 犬种表现配置 | 模型、骨骼映射、动画映射、身体区域、体型、叫声、专属动作和行为倾向 | 每个犬种独立 |
| 个体数据 | 名字、性格、偏好、亲密度、已学指令、互动记忆和成长记录 | 每只宠物独立 |

新增犬种时，主要工作是制作和适配该犬种的资源，再使用公共互动系统。只有当新犬种带来通用系统尚不支持的动作能力时，才扩展公共能力接口。

### 2.3 每个犬种需要提供的内容

| 内容 | 具体要求 |
|---|---|
| 外观模型 | 高低画质模型、材质、毛色和体型比例 |
| 骨骼适配 | 根骨骼、身体主干、头部、耳朵、四肢、爪子和尾部的语义映射 |
| 基础动画 | 待机、行走、奔跑、转向、坐下、趴下、起身、睡眠 |
| 生活动画 | 嗅闻、进食、喝水、伸懒腰、打哈欠、抓痒 |
| 互动动画 | 摸头、摸背、摸下巴、摇尾、靠近、开心和不满反馈 |
| 玩耍动画 | 追逐、叼取、携带、放下；按犬种能力增加接飞盘、拔河等动作 |
| 表情与声音 | 眼睛、耳朵、口鼻、尾巴表现，以及吠叫、呜咽和喘气 |
| 身体交互区域 | 头、耳、脸颊、下巴、背、侧腹、肚皮、四肢、爪子和尾巴 |
| 体型参数 | 缩放、脚底高度、碰撞范围、步幅、移动速度和转向速度 |
| 犬种行为倾向 | 活动、探索、玩具和互动的默认权重 |

### 2.4 共同行为与犬种专属动作

共同行为提供统一的动作语义。例如所有犬都能执行坐下、行走、进食、喝水和追球，但实际播放的动画由犬种配置决定。

犬种专属动作可以体现体态与个性，例如：

- 某些犬种更明显的卷尾、摇尾或耳朵动作。
- 不同犬种独有的坐姿、趴姿和起身方式。
- 不同犬种接近玩家、叼玩具或表达兴奋的方式。
- 体型较小的犬种可以有更轻快的步态，体型较大的犬种可以有更沉稳的步态。

专属动作作为扩展能力注册。公共行为系统负责决定何时触发，犬种表现层负责具体播放方式。缺少专属动作时使用经过验证的通用动作回退。

## 3. 性格、偏好与记忆

犬种与个体性格分别影响行为：

- 犬种提供默认倾向，例如活动强度、探索兴趣、玩具偏好和动作表现。
- 个体性格提供个体差异，例如活泼、黏人、慢热。
- 当前需求和情绪决定此刻是否愿意执行行为。
- 互动记忆影响宠物对玩家和环境的熟悉程度。

首批性格：

| 性格 | 行为倾向 | 互动表现 |
|---|---|---|
| 活泼 | 更容易探索、追球和主动玩耍 | 反应快、活动多、容易兴奋 |
| 黏人 | 更频繁关注玩家并靠近 | 喜欢跟随、主动求摸、回应呼唤 |
| 慢热 | 更常先观察，再逐渐接近 | 初期谨慎，熟悉后主动互动 |

性格不是固定动画标签。同一性格应通过多种行为概率、选择偏好和反馈方式体现，不让所有活泼犬都播放完全相同的动作序列。

## 4. 自主行为与行为 AI

### 4.1 目标

宠物在玩家不操作时仍然有可信的生活节奏。它会根据自身需求、性格、环境和最近发生的事件选择行为。

### 4.2 行为决策输入

- 需求：饱腹、水分、精力、清洁度、心情。
- 环境：玩家位置、玩具位置、食盆、水盆、狗窝、家具和场景声音。
- 个体：犬种倾向、性格、亲密度和已形成的偏好。
- 记忆：最近一次抚摸、玩耍、训练、受惊或发现物品的时间。
- 行为约束：可达路径、空间、安全距离、动作冷却和当前动作是否可打断。

### 4.3 行为选择

采用 Utility AI（效用 AI）为候选行为评分，再选择当前最合适的行为。候选行为包括：

- 观察玩家、听声音、转头和歪头。
- 嗅闻地面、调查物品和探索房间。
- 自主玩球、叼玩具和休息。
- 寻找食盆、水盆或狗窝。
- 伸懒腰、打哈欠、舔嘴、抓痒和整理毛发。
- 主动靠近玩家、等待抚摸或在附近休息。

行为必须具备触发条件、效用评分、执行状态、持续时间、冷却和中断规则。行为结束后重新评估环境，不使用固定时间随机切换动画作为主要决策方式。

### 4.4 行为反馈与记忆

宠物可以记住近期发生的有限事件，例如玩家刚刚陪它玩球、某个玩具经常被使用、某个区域发现过物品。记忆影响后续行为选择，并可在成长记录中沉淀为重要事件。

## 5. 语音交流与训练

### 5.1 交流

- 玩家可以呼唤宠物名字。
- 宠物根据距离、注意力、心情、性格和熟悉程度回应。
- 后续支持麦克风识别名字和已学习的简单指令。
- 语音输入不可用时，提供按钮或文字输入替代方式。

### 5.2 训练循环

训练由“发出指令—宠物尝试—玩家反馈—奖励—重复练习—掌握”组成。

首批指令：

| 指令 | 目标动作 |
|---|---|
| 坐下 | Sit |
| 趴下 | LieDown |
| 握手 | Paw |
| 过来 | Come |
| 等待 | Stay |
| 转圈 | Spin |

训练需要表现出学习过程：初次训练可能不理解或分心；重复练习后成功率提高；熟练后可以在日常场景中使用。玩家可用零食、抚摸和积极反馈作为奖励。

每项指令记录学习阶段、熟练度、最近训练时间和成功表现。训练难度以陪伴体验为先，不设计高惩罚失败机制。

## 6. 玩具与照料系统

### 6.1 玩具

| 玩具 | 核心玩法 | 可延伸内容 |
|---|---|---|
| 网球 | 抛出、追逐、叼回 | 自主玩球、不同距离和方向 |
| 飞盘 | 投掷、追逐、跳跃接取 | 飞盘比赛、接取动作 |
| 绳结 | 玩家与宠物拔河 | 力量反馈、松口与再咬住 |
| 毛绒玩具 | 叼取、搬运、摇晃 | 自主寻找、抱着休息 |
| 发声玩具 | 声音吸引注意 | 寻声、调查和反应 |
| 漏食玩具 | 推动、嗅闻和探索 | 难度等级、零食奖励 |

玩具应有世界内位置和状态。宠物能够看到、接近、选择和使用玩具；玩家操作是引导方式之一，不是唯一触发方式。

### 6.2 日常照料

- 喂食：食物种类、份量和进食反馈。
- 喝水：水盆补充和饮水反馈。
- 梳毛：不同工具与犬种毛发适配。
- 洗澡：打湿、涂抹、冲洗、擦干和吹干。
- 零食：日常奖励和训练奖励。
- 休息：狗窝、地毯和其他舒适区域。

照料数值影响宠物舒适度和行为选择。长时间未登录可以让宠物显得饥饿或疲惫，但不设置死亡、永久损失或强制上线惩罚。

## 7. 散步与探索

散步把活动空间从室内扩展到户外。玩家选择路线，宠物跟随并对沿途环境作出反应。

主要内容：

- 公园、街道、林间步道和海边等场景。
- 路边嗅闻点、可调查物品和环境声音。
- 宠物主动停留、观察、嗅闻或发现物品。
- 偶遇其他犬只或环境事件。
- 获得纪念品、零食、玩具和照片素材。
- 记录路线、见闻和散步照片。

散步节奏以陪伴和观察为主，不把路线设计成单纯的自动寻路过程。

## 8. 比赛与挑战

### 8.1 服从训练

玩家发出连续指令，宠物完成动作。根据识别正确率、反应时间、连续完成情况和训练熟练度评分。

### 8.2 飞盘比赛

玩家控制投掷方向和力度，宠物追逐并尝试接取。根据接取成功、距离、动作表现和完成时间评分。

### 8.3 敏捷比赛

场地包含跨栏、钻隧道、绕桩和跳跃等障碍。玩家通过指令和引导让宠物完成路线。

比赛奖励用于解锁玩具、装饰、称号和照片内容。比赛结果不影响宠物基础照料和亲密关系。

## 9. 房间、装饰与成长记录

房间物品既是装饰，也是宠物生活环境的一部分：

- 狗窝影响休息位置选择。
- 窗边垫可以成为观察环境的目标。
- 玩具架提供自主选择玩具的来源。
- 地毯和家具影响可行走区域与寻路。
- 不同装饰可以形成照片背景和纪念场景。

成长记录包括宠物照片、已学指令、比赛成绩、散步见闻、首次完成的互动和特殊行为。玩家可以回看宠物与自己共同经历的事件。

## 10. 开发优先级

| 优先级 | 系统 | 目标 |
|---|---|---|
| P0 | 多犬种模型与动作适配框架 | 复用通用功能，允许不同犬种使用自己的模型、骨骼和动作 |
| P0 | 自主行为与性格 AI | 让宠物能主动生活，并表现犬种和个体差异 |
| P1 | 语音交流与训练 | 通过名字和指令建立更深入的交流与学习 |
| P1 | 玩具与日常照料 | 丰富每天的互动方式和自主玩耍 |
| P1 | 第二犬种接入验证 | 验证新增犬种主要通过资源与配置接入 |
| P2 | 散步、比赛与探索 | 建立室内之外的活动和长期目标 |
| P2 | 犬种库、房间与成长记录 | 持续扩充犬种、生活空间和回忆内容 |

## 12. 阶段验收标准

### 多犬种框架

- 当前秋田犬的既有互动全部通过回归测试。
- 新犬种通过独立配置提供模型、骨骼、动作、触摸区域和体型参数。
- 通用互动代码不直接引用具体犬种的骨骼名称和动画名称。
- 至少两种犬可以完成同一套核心互动。
- 每种犬都至少有一组能够被玩家观察到的专属动作或反应。

### 自主行为

- 无玩家输入时宠物会持续执行合理的生活行为。
- 行为受需求、环境、犬种倾向和个体性格影响。
- 行为能够被玩家互动打断，并在合适时恢复。
- 不出现频繁随机切换、穿越障碍和无目标来回移动。

### 训练与照料

- 玩家可以训练并保存至少三项指令。
- 玩具具有不同的操作和反馈方式。
- 宠物能够自主发现或选择至少一种玩具。
- 照料动作与状态变化、动画反馈保持一致。

### 户外与比赛

- 散步路线中存在可触发的探索事件。
- 至少两种比赛能够完整游玩、结算并再次挑战。
- 相关奖励和成长记录能够保存。

## 13. 当前实现边界

截至当前原型，项目已经实现秋田犬模型加载、室内自主走动、坐下与打盹、分部位抚摸、呼唤靠近、喂食、喝水、追球叼回、梳毛和云端宠物状态。

多犬种资源适配层、完整 Utility AI、语音指令学习、飞盘与拔河、洗澡、散步、比赛和成长相册仍属于后续设计与开发内容。当前 Akita 实现包含模型专属骨骼名称、动画片段和体型参数，需先整理为犬种适配配置，再接入第二犬种。
