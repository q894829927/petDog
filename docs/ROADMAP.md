# 倩岚汪 — 开发路线图

路线以可运行、可验证的体验为阶段门槛。每阶段完成后再扩展下一批系统。

## P0：项目骨架与柴犬原型

UI 设计基线参见 [UI_DESIGN_BASELINE.md](UI_DESIGN_BASELINE.md)。当前用 Akita 资产验证 GLB 模型和骨骼动画，支持在地毯内随机选点走动、避开道具、待机和坐下。正式柴犬资源待接入。

目标：浏览器中出现一只可观察、可互动的柴犬。

- [ ] 初始化 npm workspaces。
- [x] 创建 React + TypeScript + Vite 前端。
- [x] 创建 Three.js / React Three Fiber 基础 3D 场景。
- [ ] 加载第一版柴犬 GLB。
- [x] 实现相机、地面、房间和基础灯光（程序化原型）。
- [ ] 实现待机、走动、坐下、趴下、摇尾等基础动画。
- [ ] 实现简单自主行为选择。
- [x] 完成桌面与手机的 Warm Flat HUD 基础布局。

验收：能打开网页看到柴犬；柴犬会自主切换待机行为并在限定区域活动；鼠标和触摸输入可命中宠物。

## P1：互动体验

目标：玩家能完成一轮有反馈的照顾和玩耍。

- [ ] 抚摸头部和背部。
- [ ] 呼唤名字并得到回应。
- [ ] 食物和水盆交互。
- [x] 丢球、追球和叼回（Akita 场景原型）。
- [ ] 梳毛。
- [ ] 状态 UI 和互动反馈。
- [ ] 互动动作与动画状态机衔接。
- [ ] 音效与简单环境声。

验收：每种互动都有清楚的动作反馈和状态变化；重复输入不会导致动画或数值异常。

## P2：账号、云端存档与自然时间

目标：实现真实账号和跨设备持续养成。

- [ ] Fastify API 和 SQLite 数据库。
- [ ] 注册、登录、退出和 Session。
- [ ] 首次领养、名字和性格设置。
- [ ] 宠物状态服务端结算。
- [ ] 互动 API、事务和幂等处理。
- [ ] 多设备版本冲突处理。
- [ ] 页面重新进入和恢复焦点时同步。
- [ ] 离线数小时状态结算测试。
- [ ] 账号数据隔离测试。

验收：同一账号在两台设备上看到同一只柴犬；离线时间按服务器时间结算；服务端状态是唯一权威存档。

## P3：宠物个性与成长

- [ ] 三种性格的行为参数。
- [ ] 互动偏好与记忆。
- [ ] 年龄和成长记录。
- [ ] 更多自主行为和环境目标。
- [ ] 更丰富的情绪动作。
- [ ] 宠物照片和成长记录。

## 当前优先级

第一优先级是 P0：先确认柴犬模型、骨骼和动画能在浏览器中稳定运行。模型与动画是后续抚摸、玩耍和自主行为的基础。

第二优先级是 P1：让柴犬对玩家输入产生有辨识度的反馈，形成核心体验。

第三优先级是 P2：把已验证的互动状态接入账号和云端存档，完成跨设备同步与离线结算。

不要在 P0 阶段提前开发商城、多宠物、社交或复杂任务系统。
