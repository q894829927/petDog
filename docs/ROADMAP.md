# 倩岚汪 — 开发路线图

路线以可运行、可验证的体验为阶段门槛。当前秋田犬（Akita）是验证原型；后续犬种通过资源配置与适配层接入。阶段描述的是目标状态，未完成的功能保持未勾选。

## P0：通用宠物框架与当前原型稳定

目标：把现有秋田犬互动原型整理成可复用的宠物运行框架，为后续导入不同犬种打基础。

- [x] 创建 React + TypeScript + Vite 前端。
- [x] 创建 Three.js / React Three Fiber 基础 3D 场景。
- [x] 加载秋田犬 GLB 高低画质模型并播放现有骨骼动画。
- [x] 实现相机、地面、房间和基础灯光。
- [x] 在地毯内选点走动、避开道具、坐下待机和打盹。
- [x] 完成桌面与手机的 Warm Flat HUD 基础布局。
- [x] 实现头部、脸颊、下巴、背部、身体侧面、腹部和尾根等部位的触摸反馈。
- [x] 实现呼唤、喂食、喝水、追球叼回、梳毛和侧躺互动。
- [ ] 定义犬种资源清单与统一动作语义。
- [ ] 将模型、骨骼、触摸区域和动画名称映射移入犬种适配配置。
- [ ] 将通用互动流程从 AkitaDog 组件中拆分，避免通用系统直接依赖秋田犬骨骼名称和动画片段。
- [ ] 为缺少专属动作的犬种定义通用动作回退规则。
- [ ] 建立每个犬种的模型导入和互动回归清单。

验收：当前秋田犬的已有互动不回退；犬种资源、骨骼和动作映射由独立配置提供；通用系统只调用语义动作和语义触摸区域。

## P0：自主行为与性格 AI

目标：让宠物在玩家不操作时也能自然生活，并体现犬种与个体差异。

- [x] 实现房间内自主选点行走、避障、坐下和休息。
- [ ] 引入 Utility AI（效用 AI）行为评分与优先级选择。
- [ ] 增加嗅闻、观察、伸懒腰、打哈欠、舔嘴、抓痒和自主玩耍等行为。
- [ ] 让饥饿、口渴、精力、心情和环境刺激影响行为选择。
- [ ] 将犬种行为倾向与个体性格参数分开。
- [ ] 建立短期记忆：记住玩家最近的互动、玩具位置和刚发生的事件。
- [ ] 支持行为中断、恢复、冷却和动作衔接。
- [ ] 验证活泼、黏人、慢热三种性格具有可辨认差异。

验收：宠物在无输入时持续产生合理活动；状态、环境、犬种和性格变化能改变行为选择；行为不会频繁无原因切换。

## P1：语音交流与训练

目标：让玩家能通过名字和简单指令与宠物交流，并通过重复训练形成可持续的技能成长。

- [ ] 呼唤宠物名字并根据距离、注意力和性格回应。
- [ ] 接入可用的语音输入能力，并提供按钮或文字替代方式。
- [ ] 实现坐下、趴下、握手、过来、等待和转圈等训练动作。
- [ ] 建立训练示范、重复、奖励、失败反馈和熟练度。
- [ ] 记录已学习指令及其掌握程度。
- [ ] 为不同犬种配置动作映射和专属训练表现。

验收：玩家可以教会宠物至少三项指令；训练结果能保存；重新进入后仍能调用已学会的指令。

## P1：玩具与日常照料

目标：把现有单一玩球和基础喂食扩展成可持续的日常互动。

- [x] 网球抛掷、追逐、叼回。
- [x] 狗粮、清水和梳毛原型。
- [ ] 飞盘抛掷、追逐和接取。
- [ ] 绳结拔河。
- [ ] 毛绒玩具叼取和自主玩耍。
- [ ] 发声玩具与漏食玩具。
- [ ] 零食背包和训练奖励。
- [ ] 洗澡、冲洗、擦干和吹干流程。
- [ ] 玩具偏好、使用记录和宠物自主选择玩具。

验收：至少三种玩具具有不同操作方式；宠物能主动选择或回应玩具；照料动作与状态变化一致。

## P1：第二犬种接入验证

目标：用第二种犬验证多犬种适配架构，证明新增犬种不需要重写通用玩法。

- [ ] 选定第二犬种并准备模型、骨骼和基础动画资源。
- [ ] 完成犬种配置、动作映射、触摸区域和体型参数。
- [ ] 复用已有抚摸、呼唤、喂食、玩球、梳毛和自主行为。
- [ ] 增加至少一项能够体现该犬种特点的专属动作或反应。
- [ ] 对两种犬执行同一套互动回归测试。

验收：第二犬种接入不修改通用互动流程；两种犬都能完成共同动作，并保留各自外观和动作差异。

## P2：散步、比赛与探索

目标：从室内陪伴扩展到户外活动和长期游玩目标。

- [ ] 玩家选择散步路线，宠物能够跟随。
- [ ] 增加嗅闻点、调查物品、环境声音和偶发事件。
- [ ] 增加公园、街道、林间步道等户外场景。
- [ ] 实现服从训练挑战。
- [ ] 实现飞盘比赛。
- [ ] 实现跨栏、钻隧道和绕桩等敏捷比赛。
- [ ] 比赛奖励可用于解锁玩具、装饰和纪念内容。
- [ ] 保存散步见闻、比赛成绩和探索记录。

验收：散步过程包含可互动事件；至少两种比赛可以完整游玩、结算和重复挑战。

## P2：犬种库、房间与成长记录

目标：持续增加可领养犬种，并让宠物的生活空间和成长经历具有长期价值。

- [ ] 建立犬种选择与资料展示界面。
- [ ] 按资源完成度分批接入更多犬种。
- [ ] 每种犬提供基础动作集和至少一组专属动作。
- [ ] 增加狗窝、地毯、玩具架和窗边垫等家具。
- [ ] 家具和摆件可以成为宠物自主行为目标。
- [ ] 增加项圈、围巾、帽子等装饰。
- [ ] 增加照片、成长记录、训练成果和散步相册。

验收：犬种扩充主要通过资源和配置完成；房间物品能够参与宠物行为；成长记录可以持续保存。

## P3：发布与持续运营

- [x] 前端静态自动部署。
- [x] API 构建、测试和 release 工作流。
- [ ] 后端独立自动部署与回滚。
- [ ] 数据库定时备份和恢复演练。
- [ ] 桌面与真实手机性能测试。
- [ ] 账号安全与异常请求测试。
- [ ] 公开测试和反馈收集。

## 当前开发优先级

1. 先完成 P0 的犬种适配层和自主行为系统。继续在秋田犬上验证，避免把当前 Akita 专属实现直接复制到其他犬种。
2. 再做 P1 的语音训练、玩具照料，并尽早接入第二犬种进行架构验收。
3. 最后扩展 P2 的散步、比赛、探索、犬种库和成长内容。

详细玩法、内容规则和验收标准见 [游戏内容设计文档](GAME_CONTENT_DESIGN.md)。技术适配方案见 [技术设计文档](TECHNICAL_DESIGN.md)。

不要在通用框架尚未验证前批量导入犬种，也不要把犬种专属动画和骨骼名称写入通用行为逻辑。
